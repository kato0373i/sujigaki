# RDRA の関連データ形式の調査

FR-051（書き出し）と FR-052（読み込み）で扱う、RDRA の関連データ形式を調べた結果をまとめる。調査日は 2026-11-19。

## 調べた資料

- RDRA 定義・分析シート（Google スプレッドシート）の「■関連データ」シート。[rdra.jp の紹介ページ](https://www.rdra.jp/rdra%E3%83%84%E3%83%BC%E3%83%AB/rdra%E5%AE%9A%E7%BE%A9%E5%88%86%E6%9E%90sheet) から公開されているテンプレートを TSV で取得した
- [RDRAGraph2 の関連データ作成方法](https://vsa.co.jp/rdratool/rdragraph2/v0.5/relation-data-guide.html)
- [RDRAGraph の紹介ページ](https://www.rdra.jp/rdra%E3%83%84%E3%83%BC%E3%83%AB/rdragraph%E3%83%84%E3%83%BC%E3%83%AB)

## 形式

- テキストの1行が1種類の関係を表す。列はタブで区切る。
- 1行目はシステム名の行で、2行目以降が関係の行になる（RDRAGraph2 の資料による）。
- 関係の行は次の4列からなる。

| 列 | 内容 | 例 |
|---|---|---|
| A | 関係の種類を表すタグ | `#edge` |
| B | 関係の元の要素の種類 | `UC` |
| C | 関係の先の要素の種類 | `画面` |
| D | 要素の名前の組。元と先の名前を `@@` でつなぎ、組どうしを `//` でつなぐ | `申込を登録する@@申込入力//申込を承認する@@申込一覧` |

- 要素は名前で識別する。ID の列はない。
- 状態の名前はすべての状態モデルを通して一意である必要がある（RDRAGraph2 の資料による）。
- 定義・分析シートではこの4列（A〜D）を RDRAGraph の取り込み画面に貼り付けて使う。

## 関係のタグ

| タグ | 意味（資料とテンプレートから読み取れる範囲） |
|---|---|
| `#child` | 親子関係（業務と BUC、状態モデルと状態など） |
| `#edge` | 向きを持たないつながり |
| `#arrow` | 向きを持つ流れ（アクティビティの順序、状態の遷移など） |
| `#attribute` | 情報の属性、バリエーションの値 |
| `#comment` | 要素の説明 |
| `#stereotype` | 状態のステレオタイプ |

タグの正式な定義は資料に書かれていない。上の意味はテンプレートの行の組み合わせから読み取ったものである。

## sujigaki への影響

1. 要求は関連データに含まれない。定義・分析シートには「機能要求」「非機能要求」のシートがあるが、関連データには要求の行がない。そのため、要求とそのつながりは、関連データでは書き出せず、読み込みでも変わらない。
2. このツール独自の属性も含まれない。活動の担当者や区分、確認状態、未解決の問い、外部リンクは、関連データでは書き出せない。
3. 名前の変更は別の要素の追加と見分けられない。ID がないため、FR-052 の「名前の変更が疑われる要素を利用者に確認する」手順が必要になる。
4. 状態の名前は一意にする必要がある。sujigaki のモデルで状態モデルごとに同じ名前の状態がある場合、書き出しの前に名前を変える必要がある。

## 確認できなかったこと

- テンプレートには D 列のデータが入っていないため、定義・分析シートが出力する D 列の形式は、RDRAGraph2 の資料のサンプルでしか確かめていない。RDRAGraph（v0.96）が同じ形式を受け付けるかも、実データでは確かめていない。
- 文字コードはどの資料にも書かれていない。
- 1行目のシステム名の行が定義・分析シートの出力にも含まれるかは確かめていない（テンプレートの1行目は空だった）。
